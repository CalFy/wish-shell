# wish — простий командний інтерпретатор

Лабораторна робота з курсу «Паралельне та розподілене програмування».
Реалізація завдання [OSTEP processes-shell](https://github.com/remzi-arpacidusseau/ostep-projects/blob/master/processes-shell/README.md) мовою C++.

Виконав: Коровін Микита, група ТК-32, КНУ ім. Тараса Шевченка, ФКНК.

## Збирання та запуск

```
make            # збирає ./wish
./wish          # інтерактивний режим (запрошення "wish> ")
./wish file     # пакетний режим: команди читаються з файлу
make test       # запуск офіційних тестів OSTEP (22 тести)
```

## Можливості

| Що | Приклад |
|----|---------|
| Запуск програм з каталогів `path` | `ls -la /tmp` |
| `exit` — вихід (без аргументів) | `exit` |
| `cd` — зміна каталогу (рівно 1 аргумент) | `cd /tmp` |
| `path` — заміна списку каталогів пошуку | `path /bin /usr/bin` |
| Перенаправлення stdout і stderr у файл | `ls > out.txt` |
| Паралельні команди | `cmd1 & cmd2 args & cmd3` |

Будь-яка помилка друкує в stderr єдине повідомлення `An error has occurred`.
Якщо shell запущено з більш ніж одним файлом або файл не відкривається — вихід з кодом 1.

## Як це працює

1. `main()` читає рядки через `getline()` — зі `stdin` або з файлу.
2. `process_line()` ділить рядок за `&` на окремі команди.
3. `parse_command()` розбирає кожну команду: шукає `>`, перевіряє синтаксис
   (один `>`, є команда, рівно один файл), ділить на слова.
4. Вбудовані команди (`run_builtin`) виконуються в самому shell —
   `cd` і `path` мають змінювати стан саме батьківського процесу.
5. Зовнішні команди (`launch`): пошук файлу через `access(X_OK)` у каталогах
   `path` → `fork()` → у дитині `open()` + `dup2()` для `>` → `execv()`.
6. Після запуску всіх команд рядка батько чекає кожну дитину через `waitpid()` —
   тому команди, розділені `&`, працюють паралельно.
